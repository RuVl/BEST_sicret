# Реализация функционала "Запросить рефанд"

## Описание

Реализован функционал "Запросить рефанд" для Telegram-бота, позволяющий пользователям:
- Заполнять форму заявки на возврат личных средств, потраченных на нужды BEST
- Просматривать и редактировать данные заявки перед отправкой
- Получать подтверждение о принятии заявки
- Автоматически создавать связанные записи в базе данных (Payment и Refund)

## Команда бота

- `/request_refund` - запускает диалог "Запросить рефанд"

## Структура базы данных

Функционал использует существующие таблицы:

### Таблица `payments`
```sql
CREATE TABLE payments (
    id INTEGER PRIMARY KEY,
    cost INTEGER NOT NULL,
    is_paid BOOLEAN DEFAULT FALSE,
    created_date DATETIME NOT NULL,
    bill VARCHAR(255),
    payed_date DATETIME
);
```

### Таблица `refunds`
```sql
CREATE TABLE refunds (
    id INTEGER PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    customer_id INTEGER NOT NULL,
    payment_id INTEGER NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES persons(id),
    FOREIGN KEY (payment_id) REFERENCES payments(id)
);
```

## Поток работы функционала

### 1. Главная форма
При вызове команды `/request_refund` пользователь видит:
- Описание: "Рефанд - это возможность вернуть потраченные на нужды Best'a личные средства."
- Инструкцию: "Чтобы запросить рефанд Вам необходимо указать следующие данные"
- Текущие значения полей (или "Не заполнено")
- Кнопки для заполнения полей:
  - **"Имя"** - ввод имени заявителя
  - **"Мероприятие"** - ввод названия мероприятия
  - **"Причина"** - ввод причины запроса рефанда
  - **"Сумма"** - ввод суммы в рублях (только число)
  - **"Номер карты"** - ввод номера карты для возврата
- Кнопка **"Просмотр заявки"** для перехода к финальному просмотру

### 2. Ввод данных
Пользователь может заполнять поля в любом порядке:
- При нажатии на кнопку поля открывается окно ввода
- После ввода значения пользователь возвращается к главной форме
- Значение сохраняется и отображается в главной форме
- Для суммы выполняется валидация (только числа)

### 3. Просмотр формы для редактирования
- Отображается "Повторный показ итогового варианта заявки"
- Показываются все заполненные данные
- Кнопка "Подтвердите отправку заявки"
- Кнопка "Назад" для возврата к редактированию

### 4. Просмотр итоговой заявки
- Отображается финальная версия заявки со всеми данными
- Кнопка "Подтвердить отправку заявки"
- Выполняется проверка заполнения всех полей
- Кнопка "Назад" для возврата к редактированию

### 5. Подтверждение и создание заявки
- Создается запись `Payment` с указанной суммой
- Создается запись `Refund` с данными из формы:
  - `name` - имя заявителя
  - `description` - объединенная информация (мероприятие, причина, номер карты)
  - `customer_id` - ID пользователя
  - `payment_id` - ID созданного платежа
- Казначей получает уведомление (если `TREASURER_ID` настроен)
- Пользователь видит сообщение об успешной отправке

### 6. Подтверждение отправки
- Отображается сообщение: "Ваша заявка принята, Казначей свяжется с Вами в ближайшее время"
- Кнопка "В главное меню" для возврата к форме

## Поля заявки

### Имя (name)
- Тип: текст
- Обязательное: да
- Хранится в: `Refund.name`

### Мероприятие (event)
- Тип: текст
- Обязательное: да
- Хранится в: `Refund.description` (часть описания)

### Причина (reason)
- Тип: текст
- Обязательное: да
- Хранится в: `Refund.description` (часть описания)

### Сумма (amount)
- Тип: число (целое)
- Обязательное: да
- Валидация: только числа
- Хранится в: `Payment.cost`

### Номер карты (card_number)
- Тип: текст
- Обязательное: да
- Хранится в: `Refund.description` (часть описания)

## API методов

### `create_payment()`
```python
async def create_payment(
    session: AsyncSession,
    cost: int,
    is_paid: bool = False,
    bill: Optional[str] = None,
    payed_date: Optional[datetime] = None,
) -> Payment
```
Используется для создания платежа с указанной суммой.

### `create_refund()`
```python
async def create_refund(
    session: AsyncSession,
    name: str,
    customer_id: int,
    payment_id: int,
    description: Optional[str] = None,
) -> Refund
```
Используется для создания заявки на рефанд.

## Валидация данных

### Сумма
- Проверяется, что введенное значение является числом
- При неверном формате пользователь получает сообщение об ошибке
- Значение преобразуется в `int` перед сохранением

### Обязательные поля
- Перед переходом к итоговому просмотру проверяется заполнение всех полей
- Если какое-то поле не заполнено, пользователь получает предупреждение

## Уведомления

При создании заявки казначей получает сообщение с информацией:
- Имя заявителя
- Название мероприятия
- Причина запроса рефанда
- Сумма в рублях
- Номер карты
- ID заявки

Уведомление отправляется только если `TREASURER_ID` настроен в `.env`.

## Настройка окружения

Используется существующая переменная окружения:
```env
TREASURER_ID=telegram-id  # Telegram ID казначея для получения уведомлений
```

## Особенности реализации

### Структура данных
- Данные формы хранятся в `dialog_manager.dialog_data` во время сессии диалога
- При создании заявки данные преобразуются в структуру БД:
  - Сумма сохраняется в `Payment.cost`
  - Остальные данные объединяются в `Refund.description` в формате:
    ```
    Мероприятие: {event}
    Причина: {reason}
    Номер карты: {card_number}
    ```

### Связь между Payment и Refund
- Сначала создается `Payment` с суммой
- Затем создается `Refund`, связанный с созданным `Payment` через `payment_id`
- Это обеспечивает целостность данных и возможность отслеживания платежей

### Обработка ошибок
- Проверка существования пользователя в БД
- Валидация суммы (только числа)
- Проверка заполнения всех обязательных полей
- Обработка ошибок создания записей в БД
