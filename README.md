# BEST_sicret

Монорепозиторий сервисов СПб BEST: Telegram-бот для внутренних документов, имущества, возмещений и VPN и сервис
синхронизации участников из Google Sheets в Postgres.

| Каталог               | Что это                                                            |
|-----------------------|--------------------------------------------------------------------|
| `bot/`                | Telegram-бот на aiogram 3 и aiogram-dialog 2 ([README](bot/README.md)) |
| `members_sync/`       | Ежедневная синхронизация участников ([README](members_sync/README.md)) |
| `packages/db/`        | `best_db`: все модели и единый alembic ([README](packages/db/README.md)) |
| `postgres/`, `redis/` | Конфиги `.env` для docker-compose                                  |

Каждый сервис - отдельный проект со своим venv и engine, общая только схема БД.

## Первый запуск

Нужны `uv`, `docker compose` или `podman-compose` и аккаунт Telegram с ником. Доступ к Google-таблице, панели 3x-ui и
настоящим шаблонам не нужен.

1. Создайте своего бота: `/newbot` у [@BotFather](https://t.me/BotFather), сохраните токен.
2. `make init` - зависимости, конфиги, postgres и redis, миграции.
3. Впишите токен в `bot/.env`: `TG_API_TOKEN=...`. Больше ничего менять не нужно.
4. `make dev-member who=@ваш_ник` - без этого в меню не будет кнопок: их видят только участники из локальной БД.
5. `make run-bot`.
6. Отправьте своему боту `/start`. Откроется меню, в «Создать приказ» будет демо-шаблон. VPN без панели выключен.

Другие команды: `make test`, `make lint`, `make help`. Правила кода - в [CLEAN_CODE.md](CLEAN_CODE.md), обзор
архитектуры - в [CLAUDE.md](CLAUDE.md).

## Словарь

| Термин       | Значение                                                                                                   |
|--------------|------------------------------------------------------------------------------------------------------------|
| LBG          | Local BEST Group, локальная группа BEST, здесь СПб.                                                        |
| board        | Руководство LBG: участники с категорией `board`. Роль (президент, казначей, VP4HR) определяется по `status_field`. |
| VP4HR        | Vice President for Human Resources: член board, отвечает за участников. Получает сводки об отзыве VPN.     |
| `LbgMember`  | Участник из Google-таблицы, его заводит `members_sync`. В группе, пока не исключён и не пропал из таблицы (`current_member`). |
| `Person`     | Любой, кто нажал `/start`. С `LbgMember` связывается по нику Telegram, связи может и не быть.              |
| Приказ       | Внутренний документ: шаблон `<Name>.docx` и схема вопросов `<Name>.json`. Бот задаёт вопросы и присылает `.docx`. |

## Релиз

Ветки создаём от `dev`, PR открываем в `dev`, фичевые PR можно сквашить.

Выкатка из `dev` тестовая. В `main` попадает только отлаженная версия: релизный PR `dev` → `main` сливаем после
исправления всех находок ревью и только merge-коммитом. Squash оставил бы историю `dev` вне `main`, и следующий релизный
PR снова тащил бы её целиком и конфликтовал.

## Ловушка 3x-ui: `restartXrayOnClientDisable`

Xray на панели один на всех пользователей VLESS. При этой настройке, а она включена по умолчанию, выключение и удаление
активного VLESS-клиента перезапускает xray и рвёт соединения всем. Бот выключает клиентов ночью в джобе отзыва
(`bot/jobs/revoke_vpn.py`). Перед новым вызовом панели проверьте, не приводит ли он к такому перезапуску.
