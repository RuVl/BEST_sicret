# Spec: правки AmneziaWG по ревью релиза #67

Статус: **согласована** (2026-11-03). Ветка `fix/awg-review-pr67` от `dev`.

## Objective

Ревью релизного PR #67 (dev → main) нашло 15 дефектов в AmneziaWG-части бота: из них три про утечку приватного ключа в чате и падение бота на старте. В `main` должна попасть только отлаженная версия, поэтому релиз сливается после этих правок.

Пользователь — мембер LBG, который заводит устройства AmneziaWG в боте; админ — тот, кто запускает `make awg-*`.

Успех: каждый дефект из таблицы ниже закрыт, на каждый есть регрессионный тест (или явно описанная ручная проверка, если тест на aiogram-dialog непропорционально дорог), кнопки AWG-окон занимают меньше строк, `make test-bot` и `make lint` зелёные, повторное ревью `code-review high` не находит новых блокеров.

## Требования по модулям

### `config-hide`

1. **Старт бота** (№3): скрытие оставшихся конфигов идёт из `dp.startup` после настройки диалогов. Бот с записями в `awg:pending-hides` стартует всегда (тест: запуск `main()`-подобной сборки с непустым реестром не падает).
2. **Запись удаляется только после подтверждённого скрытия** (№2). Отмена таймера при остановке бота запись **не** удаляет. Ошибка Telegram при удалении — запись остаётся и будет обработана на следующем старте; «сообщение уже удалено / не найдено» считается успехом. Исключения скрытия логируются нашим кодом, а не «Task exception was never retrieved».
3. **Ни одной копии конфига вне учёта** (№1). Пока открыто окно конфига, текст/стикер пользователя удаляется и окно не пересылается заново; любая копия сообщения с конфигом, которую бот всё-таки отправил, скрывается таймером, «Готово», `/start` и скрытием при старте.
4. **Скрытие при старте не пишет в БД от имени фиктивного пользователя** (№14): `Person.full_name` не затирается пустой строкой.
5. «Готово» гасит таймер и запись в Redis — висящих задач по уже скрытому конфигу нет.

### `dialog-races`

1. Апдейты одного человека обрабатываются последовательно (изоляция событий aiogram в `Dispatcher`), поэтому второй клик видит результат первого и **не перезаписывает** `dialog_data` (№4). Повторное нажатие на платформу/«Получить конфиг» не создаёт второго устройства, клиента и конфига.
2. Неверный комментарий про «апдейты не сериализуются» исправлен по факту.
3. «Да, удалить» при закрытом доступе показывает «нет доступа», а не «Устройство удалено» (№15).

### `panel-client`

1. Тело `/clients/update` проходит разбор панели: `allowedIPs` и другие поля шлются в типах `model.Client` 3x-ui (№5). Тест-фикстура содержит строковый `allowedIPs` из реального ответа.
2. `skipped` из ответа `bulkEnable`/`bulkDisable` — это неуспех для этих email (№8): они не помечаются `revoked`/`suspended`, попадают в лог/сводку и будут повторены следующим прогоном.
3. Невалидный ответ панели (`pydantic.ValidationError`) превращается в `XuiError` (№10). В `suspend_inactive_awg_access` одна плохая запись не обрывает прогон и не приводит к повторным уведомлениям.

### `device-identity`

1. `ensure_peer` сначала ищет клиента под **новым** именем и подхватывает его; повторная попытка после сбоя посреди выдачи конфига заканчивается конфигом, а не «email already in use» (№7).
2. `escape_mdv2` экранирует `\` (№6). Проверить, что это не ломает существующих вызывающих (тест на `PC\-1`, `Ноут\`).
3. Название с ZWJ-эмодзи (👨‍💻) в пределах лимита принимается — длина считается в графемах, как видит человек, либо сообщение об ошибке говорит о реальной причине.

### `person-username`

Устаревший `telegram_username` опасен не только для CLI: по нему же `members_sync` (`link_persons`) связывает Person с LbgMember — чужой ник мог бы связать не того человека.

1. **Инвариант в БД:** частичный уникальный индекс по `lower(telegram_username) WHERE telegram_username IS NOT NULL`. Миграция перед созданием индекса обнуляет ник у всех строк-дублей (кому ник принадлежит сейчас, неизвестно — владелец вернёт его своим следующим `/start`).
2. **Захват ника:** репозиторий `database/methods/person/` получает функцию «закрепить ник за человеком»: в той же транзакции снимает этот ник (без учёта регистра) с других Person и ставит его текущему. `get_or_create_person` пользуется только ей.
3. Человек, убравший username в Telegram, теряет его и в БД (сейчас `None` игнорируется и старый ник остаётся навсегда).
4. Поиск по нику — функция репозитория, возвращает не больше одного Person (гарантия индекса); в CLI запросов к `Person` нет.

### `cli-admin`

Каркас `bot/cli/common.py` для всех команд: `CliError`, поиск человека (`@username` или Telegram ID), описание человека, подтверждение, бот для отправки, запуск с закрытием engine/клиентов.

1. **Описание человека:** `ФИО (tg 123456)` — ФИО из LbgMember (`full_name_ru`); если человек не связан с LbgMember или ФИО пусто — только `tg 123456`.
2. **Подтверждение:** каждая меняющая команда (`awg-grant`, `awg-revoke`, `broadcast`) печатает, на кого и что именно сделает (например «Выключить 2 ключа» / «Удалить 2 устройства и ключи в панели безвозвратно»), и спрашивает `Вы уверены [y/n]: `. Всё кроме `y`/`yes` (и отсутствие терминала) — отмена без изменений.
3. `delete=1` у `awg-revoke` **остаётся**: это не подтверждение, а другое действие — без него ключи выключаются и вернутся при `grant`, с ним устройства и ключи удаляются.
4. `awg-grant` пишет «Уведомление отправлено» только при успешной отправке, иначе — что не дошло.
5. **`awg-announce` удаляется** вместе с `mark_announced`, текстом `vpn-awg-announce` и колонкой `awg_access.announced_at` (миграция). №12 этим снимается.
6. **`make broadcast`** — рассылка произвольного сообщения:
   ```
   make broadcast file=msg.txt group=all              # все, кто нажимал /start
   make broadcast file=msg.txt group=awg,board        # объединение групп
   make broadcast file=msg.txt to=@ivan,123456789     # поимённо
   make broadcast file=msg.txt group=board to=@ivan   # группы + поимённо, без дублей
   ```
   - **Группы** — вычисляются из данных, без ручной разметки и новых таблиц: `all` (все, кто нажимал `/start`), `members` (активные мемберы LBG), `board` (активные из board-листа, `membership_category == 'board'`), `awg` (есть доступ AmneziaWG, не отозван), `vless` (активная VLESS-подписка). Новая группа = одна функция-запрос в репозитории и строка в реестре групп. Неизвестная группа — ошибка со списком доступных.
   - Без `group=` и `to=` команда ничего не шлёт и подсказывает синтаксис: «всем» — только явным `group=all`.
   - Текст — из файла на хосте, в MarkdownV2 как есть (Makefile копирует его в контейнер через `docker compose cp`, чтобы терминал остался свободен для `[y/n]`).
   - `to=` принимает вперемешку `@username` и Telegram ID — тот же поиск, что у `awg-*`. Ненайденные — ошибка до отправки.
   - Перед подтверждением: текст сообщения, число получателей и список `ФИО (tg …)`.
   - Ошибка разметки на первом же сообщении останавливает рассылку (иначе она упадёт у всех). Не дошедшие печатаются строкой, готовой для `to=`.
   - Темп — не больше ~10 сообщений в секунду, как сейчас.

### `settings-qr`

1. `settings.awg.ENABLED` = `INBOUND_ID > 0` **и** заданы `XUI_BASE_URL` и `XUI_API_TOKEN` (№13). Без них — предупреждение в логе старта, кнопки AWG нет, джоб не ставится.
2. **Android-конфиг и QR (№9) — решено:** файл всегда с полным `ExcludedApplications`; QR-код строится из того же конфига, но с урезанным списком — берётся максимальное начало `excluded_apps.txt` (порядок файла = приоритет: банки → госсервисы → маркетплейсы → …), при котором QR влезает. Подпись QR говорит, что в нём только N из M исключений и полный список — в файле. Если исключения не урезались (iOS/ПК) — подпись прежняя. Кнопка «Показать QR-код» у Android есть всегда.
3. `_check_endpoint` отклоняет внутренние имена (`host.docker.internal`, `localhost`, одноимённые сервисы compose), комментарий у `extra_hosts` в `docker-compose.yaml` актуализирован.

### `ui-compact`

Раскладка (согласована):

- **Клиенты для Android:** основной — WG Tunnel (Google Play, `com.zaneschepke.wireguardautotunnel` — проверить ссылку), запасной — официальный AmneziaWG (Google Play). Ссылка на APK с GitHub убирается. WG Tunnel понимает AmneziaWG 3.1 (≥ 5.6.0, лучше ≥ 5.7.5) и `ExcludedApplications`. Тексты подсказки (`vpn-awg-hint`) и рассылки (`vpn-awg-announce`) — под WG Tunnel.
- Тексты — только через Fluent (`vpn.ftl`), ключи проверяет `test_l10n_keys.py`.

### `cleanup`

В пределах затронутых файлов: общий помощник «выбыл из LBG» вместо трёх копий; `notify()` из `jobs/revoke_vpn.py` — в общий модуль с корректным ключом лога; сводка suspend-джоба — через Fluent; мёртвый `try/except` в `on_name_entered`; неиспользуемые ключи `dialog_data`.

**Вне рамок:** переписывание уже применённых миграций (они на сервере), вынос HTTP-запросов к панели из открытой DB-транзакции и два GET в `find_peer` (архитектура/производительность — отдельной задачей, если понадобится).

## Testing Strategy

- `pytest` в `bot/tests/`, по файлу на модуль (`test_pending_hides.py`, `test_awg_dialog_races.py`, `test_vpn_client.py`, …).
- Сначала тест, воспроизводящий дефект (красный), потом правка — сценарии берём из репро ревьюера в scratchpad, переводим на fake Redis/Telegram без сети.
- Логика aiogram-dialog, которую дорого поднять целиком (№1, №4), — тестом на наш guard/хэндлер плюс ручная проверка на тестовом боте из `dev` по чек-листу в PR.

## Boundaries

- **Always:** тест на каждый дефект; `make test-bot` и `make lint` перед коммитом; один модуль — один коммит; ревью `code-review high`.
- **Ask first:** новая миграция БД; новая зависимость (например, `grapheme` для ZWJ — сначала попробую без неё); изменение поведения, видимого людям сверх таблицы (тексты рассылок, лимиты).
- **Never:** правка применённых миграций; чтение `*.env`; force-push в `dev`/`main`; слияние #67 до закрытия всех модулей.
