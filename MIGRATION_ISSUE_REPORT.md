# Ошибка "relation \"persons\" does not exist"

## Описание проблемы

При вызове команды `/start` бот логировал SQL-ошибку:

```
ERROR: relation "persons" does not exist
STATEMENT: SELECT persons.id, persons.telegram_id, ...
```

Это означало, что в базе данных отсутствовала таблица `persons`, на которую делался запрос. Таблица определяется моделью `Person` и должна создаваться миграциями Alembic.

Однако проверка базы показывала только таблицу `alembic_version` и никаких остальных.

## Причины

1. Миграции не генерировались/не применялись к базе данных.
2. При создании миграций они записывались в контейнер, но не синхронизировались с хостом, поскольку сервис `telegram_bot` не монтировал каталог исходников (через `volumes`).
3. В `bot/database/migrations/env.py` присутствовала функция `process_revision_directives`, которая отбрасывала миграции без изменений (`is_empty()`), поэтому генератор просто не сохранял файлы.
4. В результате база оставалась пустой, и любой запрос к таблицам падал с описанным выше сообщением.

## Решение

1. Добавлен монтируемый том для каталога бота в `docker-compose.yaml`:

```yaml
services:
  telegram_bot:
    ...
    volumes:
      - media_volume:/usr/src/app/resources
      - ./bot:/app  # синхронизация кода с контейнером
```

2. В `bot/database/migrations/env.py` закомментирована проверка `script.upgrade_ops.is_empty()`, чтобы автогенератор всегда записывал файл миграции.

3. Удалены существующие тома PostgreSQL и перезапущена инфраструктура:

```bash
docker-compose down -v
docker-compose up -d postgres redis
```

4. Сгенерирована и применена миграция:

```bash
docker-compose run --rm telegram_bot alembic revision --autogenerate -m "Create tables"
docker-compose run --rm telegram_bot alembic upgrade head
```

5. Проверено, что в базе появились все таблицы:

```bash
docker-compose exec postgres psql -U user -d database -c "\dt"
```

6. Бот запущен и проверено, что в логах нет больше ошибок о `persons`.

## Итоги

- Ошибка возникла из-за пустой базы, созданной без миграций.
- Исправления включают добавление монтирования кода и удаление фильтра пустых ревизий.
- После выполнения миграций таблицы появились, и бот работает корректно.

> **Совет:** всегда монтируйте директорию с кодом при разработке в Docker. Это позволит миграциям и другим файлам, создаваемым внутри контейнера, попадать на хостовую машину.
